### Fluids: how full the overflows keep their pipes

Traced down from what was missing, chains ran dry five to seven levels down (lead dust, ammonium oxalate, molten
copper, molten glass), and many users stood just short of a craft's fluid: treated wood with 56 and 86 of the 100
creosote it takes, three printers with 47 to 49 of the 50 fetal serum, chromium with 92 of 100. Factorio 2.0 sizes a
machine's fluid box at about twice its recipe's amount and fills it only as full as its pipe; the test copy's fluid
overflows (an infinity pipe at each 0/s fluid output and each block's local fluid sink) held their pipes at most half
full, so a user needing half its box never got there. A maker needs the opposite: room for a batch in its box, so a
pipe below half full.

| Overflows (with virtual sinks and feeding) | Crafts | Science | Fluids the check fed (sum of shares of planned use) |
|---|---:|---|---:|
| keep pipes at most half full (test copy) | 46,498 | 92% | 9.1 |
| at most 90% full (`--overflow-keep 0.9`) | 43,296 | 50% | 6.8 |

At 90% the users came in (tin pulp fed 78% to 0%, wax 41% to 4%, liquid nitrogen, uf6, hot air) but some makers
choked on full pipes (molten chromium 36% to 76%, sb-58 concentrate, molten copper). (Science counts are a dozen packs
in ten minutes either way: noise.) Hence **gated fluid overflows** (`--fluid-gates`): shut, so pipes fill, and open
(at most half full) only while a maker of that fluid on the same pipes stands full and no user there waits.

Shut, makers choke on full pipes (cold air, vinyl acetate, jig grades, solder: all fed in full). So outlets matter,
and nine tenths is the best level tried. The real blueprint's own outlets are Py overflow valves, which pass above
about 80% full: the real factory is nearer the 90% row than the test copy's half. Why no gate opened: likely the
game names no pipe network for a machine's own fluid box, so "a user waits" meant any user of that fluid anywhere.
The report now lists both (each gate's open time, each machine box's network id).

### Fluid demand per pipe network never worked

The report of the second gated run listed, for each of the 1,198 machine fluid boxes, the same error: "LuaEntity
doesn't contain key fluidbox". The game here is **Factorio 2.1.24**, which has no `LuaFluidBox`: an entity's fluid
storages are reached through its own methods (`get_fluid_segment_id(i)`, `has_fluid_segment(i)`,
`get_fluid_filter(i)`...). The lookup ran inside a pcall, so since yesterday's commits ef1a81b/71083e5 fluid demand
per pipe network (check and mod) has always fallen back to "anywhere", and the gates never opened. Fixed in both
(commit 61611b3), with a storage that has no network of its own taking those of the pipes it connects to; the rest of
both Lua files checked against the game's own API reference (`doc-html/runtime-api.json`). Yesterday's table row
"fluid demand per pipe network" (36,449 against 33,859 crafts) was therefore noise.

shortfalls are in the steady state, not only in starting up.
